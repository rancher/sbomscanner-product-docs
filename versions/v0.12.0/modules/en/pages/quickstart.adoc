= SBOMscanner Quick Start
:revdate: 2026-10-09
:page-revdate: {revdate}

Welcome to the SBOMscanner Quick Start!

include::partial${build-type}-specific/warning.adoc[]

This guide will walk you through the following steps:

* Deploying the SBOMscanner stack in a Kubernetes cluster
* Running an automated image scan using a `Registry` custom resource

== Requirements

Before deployment, you need to prepare the following:

* A Kubernetes cluster (you can simply run a
https://kind.sigs.k8s.io/[kind] cluster)
* A
https://kubernetes.io/docs/concepts/storage/storage-classes/#default-storageclass[default
Storage Class] defined inside of the cluster
* `helm` installed locally
* `kubectl` installed locally
* Credentials for the https://apps.rancher.io[SUSE Application Collection]
* `cert-manager` installed in the cluster
* `CloudNativePG` installed in the cluster

=== Authenticate to the SUSE Application Collection

The {sboms-name} Helm chart, its dependencies, and all their container
images are distributed through the SUSE Application Collection. See the
https://docs.apps.rancher.io/get-started/authentication/[Application Collection
authentication documentation] for how to obtain your credentials.

Log in to the registry with Helm:

[source,bash]
----
helm registry login dp.apps.rancher.io \
  --username <your-username> \
  --password <your-token>
----

The cluster also needs credentials to pull the container images. Each of
the following sections creates an image pull secret named
`application-collection` in the namespace where the chart is installed.

=== Install cert-manager

To install cert-manager from the SUSE Application Collection, run the
following commands:

[source,bash]
----
kubectl create namespace cert-manager

kubectl create secret docker-registry application-collection \
  --namespace cert-manager \
  --docker-server=dp.apps.rancher.io \
  --docker-username=<your-username> \
  --docker-password=<your-token>

helm install cert-manager oci://dp.apps.rancher.io/charts/cert-manager \
  --namespace cert-manager \
  --set crds.enabled=true \
  --set 'global.imagePullSecrets={application-collection}' \
  --wait
----

[NOTE]
====
For more information on configuring cert-manager, please visit the
https://cert-manager.io/docs/installation/helm[cert-manager
documentation]
====


=== Install CloudNativePG

To install CloudNativePG from the SUSE Application Collection, run the
following commands:

[source,bash]
----
kubectl create namespace cnpg-system

kubectl create secret docker-registry application-collection \
  --namespace cnpg-system \
  --docker-server=dp.apps.rancher.io \
  --docker-username=<your-username> \
  --docker-password=<your-token>

helm install cnpg oci://dp.apps.rancher.io/charts/cloudnative-pg \
  --namespace cnpg-system \
  --set 'global.imagePullSecrets={application-collection}' \
  --wait
----

To customize the CloudNativePG installation, refer to
xref:/installation/helm-values.adoc#using-cloudnativepg-recommended[Using CloudNativePG
(Recommended)] in the Helm values documentation. You can also bring your
own PostgreSQL instance instead of using CloudNativePG. See
xref:/installation/helm-values.adoc#using-an-external-postgresql-instance[Using an
External PostgreSQL Instance] for configuration details.

== Deploy SBOMscanner

Follow these simple steps from your local machine to get SBOMscanner up
and running:

=== Install the Helm chart

Install the `suse-security-vulnerability-scanner` Helm chart from the
SUSE Application Collection:

[source,bash]
----
kubectl create namespace sbomscanner

kubectl create secret docker-registry application-collection \
  --namespace sbomscanner \
  --docker-server=dp.apps.rancher.io \
  --docker-username=<your-username> \
  --docker-password=<your-token>

helm install sbomscanner \
  oci://dp.apps.rancher.io/charts/suse-security-vulnerability-scanner \
  --version 0.12.1 \
  --namespace sbomscanner \
  --set 'global.imagePullSecrets={application-collection}' \
  --wait
----

[TIP]
====

By default, the installation of SBOMscanner is configured to be highly
available. If you want to save on resources, you can reduce the number
of replicas to the minimum by running the following `helm install`
command instead of the previous one:

[source,bash]
----
helm install sbomscanner \
  oci://dp.apps.rancher.io/charts/suse-security-vulnerability-scanner \
  --version 0.12.1 \
  --namespace sbomscanner \
  --set 'global.imagePullSecrets={application-collection}' \
  --set controller.replicas=1 \
  --set storage.replicas=1 \
  --set storage.postgres.cnpg.instances=1 \
  --set worker.replicas=1 \
  --wait
----

This configuration is suitable for development environments where high
availability is not required.
====

== Run a Scan

In this section, you’ll learn how to create a registry source and
trigger an automated scan.

=== Prepare a `registry.yaml` file

Before running a scan, you need to define a `Registry` custom resource
for SBOMscanner to fetch images.

[source,yaml]
----
apiVersion: sbomscanner.kubewarden.io/v1alpha1
kind: Registry
metadata:
  name: test-registry
  namespace: default
spec:
  uri: ghcr.io
  repositories:
    - name: kubewarden/sbomscanner/test-assets/golang
----

=== Create the Registry CR

[source,bash]
----
kubectl apply -f registry.yaml
----

=== Prepare a `scan-job.yaml`

The `ScanJob` CR tells SBOMscanner which registry to scan.

[source,yaml]
----
apiVersion: sbomscanner.kubewarden.io/v1alpha1
kind: ScanJob
metadata:
  name: test-scanjob
  namespace: default
spec:
  registry: test-registry
----

=== Create a ScanJob CR

[source,bash]
----
kubectl apply -f scanjob.yaml
----

=== Wait for Results

Once the scan completes, check the generated SBOMs and vulnerability
reports:

[source,bash]
----
kubectl get sbom -n default
kubectl get vulnerabilityreport -n default
----

You should see output like:

[source,bash]
----
NAME                                                               CREATED AT
2ca3e0b033d523509544cb6f31c626af2a710d7dbcc15cb9dffced2e4634d69b   2025-06-10T10:26:38Z
...
----

=== Summary

You’ve successfully created a real-world Registry resource and triggered
an automated scan.

You can jump to the xref:/user-guide/querying-reports.adoc[Querying
reports] guide to learn how to query and inspect the generated images,
SBOMs, and vulnerability reports.
